# 聚合统计与上传任务进度

本文记录两个功能的设计：`#/aggregate` 聚合统计，以及知识库页上传任务的逐文件进度、取消与重试。所有行为以代码为准，接口字段与 `app/web.py`、`app/service.py`、`app/uploads.py` 对齐。

## 一、聚合统计

### 目标

普通问答回答「这个问题的答案是什么」；聚合统计回答「这批材料里哪几类情况最常见」。典型问题：

> 这几份财报里，出现最多的三种经营风险是什么？

### 流程

```
聚合问题
 → 检索样本   retrieve_question()（含知识库/访问组权限过滤），取 top N 片段
 → 语义抽取   分批调用 LLM，输出 {chunk_id, relevant, category, evidence}
 → 归一聚类   bge-small 对 category 短语做 Embedding，贪心余弦聚类
 → 计数排序   按 distinct doc_id 计数（同文档同类只算 1 次），取 top-K
 → 返回证据   类别、文档数、占比、可点击原文片段
```

实现位置：

- `chains/aggregate_chain.py`：抽取 Prompt、JSON 解析、单批 LLM 调用。
- `app/aggregate.py`：检索、并发抽取、聚类、去重计数、证据整理。
- `app/aggregate_jobs.py`：进程内异步任务与进度。
- `app/web.py`：`POST /api/aggregate-jobs`、`GET /api/aggregate-jobs/{id}`。
- `app/web_static/js/views/aggregate.js`：聚合页。

### 请求与结果

`POST /api/aggregate-jobs`：

```json
{
  "question": "财报里有哪些经营风险？",
  "sample_size": 30,
  "top_categories": 3,
  "retrieval_method": "hybrid"
}
```

- `sample_size`：10–500，默认 `AGGREGATE_SAMPLE_SIZE`（200）。
- `top_categories`：1–10，默认 3。
- 其余检索参数与问答一致：`candidate_pool`、`similarity_threshold`、`fusion_method`、`fusion_k`、`fusion_alpha`。

结果：

```json
{
  "status": "completed",
  "stage": "done",
  "result": {
    "sample": {"chunks": 30, "docs": 7},
    "categories": [
      {
        "label": "信用风险",
        "doc_count": 6,
        "chunk_count": 6,
        "ratio": 0.8571,
        "evidence": [
          {"doc_id": "...", "chunk_id": "...", "title": "...", "source": "...", "snippet": "..."}
        ]
      }
    ],
    "meta": {
      "model": "...",
      "sample_size": 30,
      "similarity_threshold": 0.85,
      "relevant_chunks": 18,
      "elapsed_ms": 183400,
      "warnings": ["第 3 批抽取失败：Request timed out.", "基于召回样本估计，非全库精确计数。"]
    }
  }
}
```

### 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `AGGREGATE_SAMPLE_SIZE` | 200 | 默认召回片段数 |
| `AGGREGATE_BATCH_SIZE` | 10 | 每次 LLM 抽取的片段数 |
| `AGGREGATE_MAX_WORKERS` | 4 | 抽取并发数，实际不超过 `MAX_CONCURRENT_ANSWERS` |
| `AGGREGATE_SIMILARITY_THRESHOLD` | 0.85 | 聚类余弦阈值 |

### 限制

- **样本估计**：结果只代表召回样本，不代表全库精确计数；界面与 `meta.warnings` 都会标注样本量。
- **概率性归一**：LLM 的类别概括与聚类可能把不同情形并在一起，或把同义表述拆开；阈值可调，但结论应点击证据复核。
- **即时计算**：每次提问现算，不跨请求缓存；样本越大越准，也越慢、越贵。
- **批次降级**：单批抽取超时会记录 warning 并跳过，不会让整个任务失败；这会让计数偏少，界面会展示 warning。

## 二、上传任务进度、取消与重试

### 任务字段

`GET /api/upload-jobs` 返回的任务除原有 `id/filenames/status/files/documents/chunks` 外，新增：

```json
{
  "stage": "load",
  "progress_done": 3,
  "progress_total": 8,
  "current_file": "002714_2019_牧原股份.pdf",
  "file_details": [
    {
      "index": 0,
      "name": "002626_2019_金达威.pdf",
      "size_bytes": 6036373,
      "status": "done",
      "cache_hit": true,
      "documents": 1,
      "chunks": 494,
      "duration_ms": 215000,
      "stage": "done",
      "error": ""
    }
  ],
  "failed_files": [],
  "continue_on_error": true,
  "cancel_requested": false,
  "runtime": {
    "embedding_model": "bge-small-zh:q8_0",
    "knowledge_base_id": "default",
    "structurize_provider": "mineru",
    "mineru_model_version": "pipeline"
  },
  "queue_position": 0
}
```

- `stage`：`queued` / `load` / `split` / `vector_write` / `done` / `failed` / `cancelled`。
- `file_details[].status`：`loading` / `done` / `failed` / `skipped`。
- `cache_hit`：结构化解析是否命中 `.markdown-cache`。
- `queue_position`：排在当前任务前面的活动任务数；运行中的任务为 0。

### 状态机

| 状态 | 含义 | 后续操作 |
|---|---|---|
| `queued` | 排队中 | 可取消 |
| `indexing` | 正在处理 | 可取消（当前文件结束后生效） |
| `completed` | 全部成功 | — |
| `partial` | 部分成功 | 可重试失败文件 |
| `failed` | 全部失败 | 可重试失败文件 |
| `cancelled` | 已取消 | 已成功解析的文件仍会入库；可重试失败文件 |

### 取消语义

- 取消只检查**文件边界**：MinerU 单份解析无法中途打断。
- 排队中的任务立即取消；worker 之后取到该任务时直接退出。
- 索引中的任务置 `cancel_requested=True`，当前文件处理完后停止后续文件。
- 已经解析成功的文件仍会切片并写入向量库，不浪费已完成的解析。

### 失败继续与重试

- Web 上传默认 `continue_on_error=True`：单个文件失败会记录 `file_details` 与 `failed_files`，继续处理其余文件。
- 全部成功 → `completed`；部分成功 → `partial`；全部失败 → `failed`。
- `POST /api/upload-jobs/{id}/retry` 只为 `status=failed` 的文件创建新任务；源文件必须仍在磁盘上。
- CLI 入库保持 `continue_on_error=False`，首个失败即中止，行为与之前一致。

### 接口

- `GET /api/upload-jobs`：任务快照列表（仅管理员）。
- `POST /api/upload-jobs/{id}/cancel`：取消（仅管理员）。
- `POST /api/upload-jobs/{id}/retry`：重试失败文件（仅管理员，队列满时返回 409）。

### 已知边界

- 整批入库仍持有向量库写锁；入库期间问答与文档列表读请求会等待。
- 进度按文件数计算，不按字节/页数加权；预计剩余时间基于已完成文件的平均耗时，文件大小差异大时会偏差。
- 任务状态保存在 `.web_upload_jobs.json`；进程重启后 `queued`/`indexing` 任务会重新排队，进度字段清零，已解析文件靠 Markdown 缓存加速。
